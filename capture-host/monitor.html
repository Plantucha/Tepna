Capture streams

Only streams the device actually advertises are offered. Turning one on adds BLE traffic and disk: the estimate is measured from this host's own captures. Stream changes take effect when the device next reconnects.

Behaviour
Daemon control

Stream and rate changes only take effect at a device's next connect — restart to apply them now. Stopping frees the BLE links for a manual probe; the daemon restarts itself when the timer expires, so a forgotten stop cannot cost a night. Reload units is for after a pull changed the systemd unit itself: it re-reads the files and nothing drops, but a restart is still what carries a [Service] change into the running daemon.

Push alerts

Where the box sends a sensor-offline or low-disk alert. Any webhook that accepts a JSON POST works — ntfy, Discord, Slack, a Telegram bridge, Home Assistant. The saved address is never shown again (for these services the URL is the password); to change it, type a new one. Leave the box empty and save to keep the current one.

Streams the CPAP's flow + pressure over BLE onto the Overview Live-streams grid, live. Runs on the free radio. Whether it refuses beside a capturing wearable is conditional: the 2.4 GHz coexistence interlock is off by default (owner decision, 2026-08-23) — a start beside on-body sensors is logged, not blocked — and is restored by setting cpap.ble_stream.coexistence_gate: true. Read-only — nothing on the device is changed.

Offload target

Where finished nights go. A night is only released to the retention guard once a second copy is confirmed — so if this is broken, the box holds nights instead of deleting them, and the disk fills. That is deliberate: a full disk is recoverable, a deleted recording is not.

🔒 Vigil never stores a password. Use an SSH key (rsync) or a root-owned credentials file (SMB) and give its path — the secret stays in a file only root can read.

Closes the last measurable target of the known-clock experiment: an END-TO-END timing test for the capture write path. Phases 1-3 perturb the arrival SIDECAR, which leaves the capture daemon outside the loop — decoding a PMD frame, stamping arrival and formatting the CSV all happen before the substrate those experiments touch, so an acquisition-side defect was invisible to every one of them. `capture-host` holds a 100 % coverage floor and had **no test following a clock relationship from a wire frame to a recovered rate**. `capture-host/tests/test_write_path_clock_recovery.py` plants a known device-vs-host rate as raw PMD bytes, decodes it with the REAL `decode_frame`, writes it with the REAL `PmdArrivalLogWriter`, reads the file back and recovers the rate from the written columns — nothing reimplemented, because a test that formats its own CSV passes while the shipped formatter is broken. Planted 0 / +50 / −50 / +200 ppm over a 40-minute session at 130 Hz; each recovers within 2 ppm at the correct sign (host−device, so a fast device reads negative). Two properties are pinned separately because the rate test does not cover them: the arrival stamp keeps MILLISECOND resolution (a whole-second stamp would make every rate under ~400 ppm unrecoverable while the 200 ppm case still passed), and a missing device stamp is written blank rather than as a fabricated 0. **The tests were verified by breaking the code rather than by passing**: truncating `_phone_ts` to whole seconds kills 3 of 4, and making the blank-field helper emit "0" kills the fourth; both mutants were reverted and `writers.py` is byte-identical. A first-run pass is not evidence here — the repo's own lesson is that a gate counts only once you have seen it fail.

Stop the vigil deploy from writing the retired udev rule name, and correct three more sites that name it.

- `deploy-vigil.sh` step 5 wrote `/etc/udev/rules.d/50-tepna-btdongle.rules`. That prefix loses to Ubuntu's own `60-autosuspend.rules`. Step 5 now deletes that stale copy, and step 2c owns the install of the tracked `99-` file.
- Step 2c ran under `|| true`, so a failed `/etc` install reported success and left the losing rule. It now prints a loud failure.
- `capture.py` told the operator to install `systemd/50-tepna-btdongle.rules`, a path this tree does not hold. It now names the `99-` file.
- `test_capture_clock_and_health.py` asserted that retired name, so the suite pinned it for sixteen months. The test now reads the name off disk.
- `99-tepna-btdongle.rules` line 1 called itself `50-tepna-btdongle.rules`. It now carries its own name.
- Two new guards hold the deploy script. It installs no udev rule of its own. It swallows no failed `/etc` install.

`AUDIT-PROMPT.md` gains a 15th bug class: **the label that does not travel with its number** — an
artifact authoritative in FORM and unkeyed to its CONTENT.

It is named now because it fired FOUR times in one day across FOUR independent sessions, and no two
instances looked alike at the surface: a comparison tool printing a wrist reference beside a finger
measurement under a device default; `build-docs.mjs` printing a `git add` remediation of nine paths of
which zero had changed, omitting the one it had rewritten; `rebase-safe.mjs` printing `verDex.html` for
`OverDex.html`; and a rebase reverting a just-earned `verifiedUnder` while leaving the file's shape
intact. One of those inverted a conclusion already written into a brief.

WHY IT EARNS A CLASS RATHER THAN A LINE. A wrong value is survivable — it looks wrong, or it looks like
nothing. A wrong LABEL on a RIGHT value converts a search into a confident wrong search: absence makes
you look, a wrong pointer makes you stop looking. Three properties make it expensive, and all three were
observed rather than theorised:

  (a) A LABEL AT THE TOP DOES NOT PROTECT A NUMBER AT THE BOTTOM. The comparison tool DID print its
      device correctly, at the top; the label was lost to `| tail -20`. So this class COMPOSES with
      CLAUDE.md §👥.4b's truncation trap, and each alone is survivable. That is why the fix is not "add
      a label" — it is that the label must travel with the value it labels.
  (b) IT SURVIVES SELF-REVIEW BY CONSTRUCTION, because the wrong label is the thing you would check
      against. The instance above was caught only when a PEER challenged a number already in a brief.
      No gate here can see it and no amount of author care surfaces it.
  (c) IT IS NOT A STALE VALUE. The form is intact, so schema checks, integrity checks and diffs all
      pass; only the BINDING between label and value is broken, and nothing in this repo checks
      bindings.

The entry ships hunting instructions keyed to those properties (grep format strings holding a hardcoded
device/unit next to an interpolated value; check every remediation line against `git status --porcelain`
rather than believing it; re-verify `verifiedUnder`/`manifestHash` after any rebase; and ask whether a
report truncated to its last 20 lines would leave a number without its qualifier).

NOT DONE, deliberately: the header's `last-verified: 2026-07-18` is UNCHANGED. Adding a class is not
re-verifying the charter against the codebase, and bumping that date would be an instance of the very
class being added.

Cross-session: three sessions contributed instances; the composition insight (a) is Brief runner's,
from correcting their own first account of the trap.

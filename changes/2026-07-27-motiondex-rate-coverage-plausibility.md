Three defects in one file, landed together because they are one edit. (1) `sampleHz` returned count ÷ span — the average over the span, which any dropout depresses by exactly the coverage fraction: 18.68 Hz on a real Verity file whose median inter-sample delta is exactly 1/52 s. Every consumer treats the result as the NATIVE rate and sizes a window with it, so an under-stated rate makes actigraphy's gravity baseline, the effort drift and cardiac moving averages and the breath refractory all too short in real time. Now the median inter-sample interval, the measurement `respResample` in the same file already did correctly. (2) `respResample` filled sensor-off holes by linear interpolation and `respWindowSpectrum` normalises power away, discarding the only cue that separates "no signal" from "signal" — so a confident breathing rate was measured across epochs where the strap was not recording. Grid points interpolated across a gap wider than four native periods are now marked uncovered; a window leaning on them gets a uniform likelihood (no evidence, so the fabricated ridge cannot steer the global Viterbi track through clean windows either) and is published as `covered:false` with a null rate, leaving the coverage denominator. (3) `parseSensorXYZ` finite-checked only X and range-checked nothing, so a real capture-host file's 136 corrupt samples up to 1.6e38 mg were ingested verbatim and saturated every activity statistic while `motionSQI`'s clipFrac fraction test could not fire on 0.13 % of rows. Samples beyond hardware full scale are now dropped and counted (`_implausibleDropped`) — the PpgDex precedent, never clamped, because a clamped sample is a fabricated reading at the bound.

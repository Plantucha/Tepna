The mutation gate no longer instructs you to delete a correct equivalence claim because a contended run lost track of its mutant. `REFUTED` — the one verdict here that destroys work, since it tells a reader the recorded claim is false — was derived from ABSENCE: a mutant that mutmut generated and that did not come back a survivor was called killed. A reaped worker, a partial run and a shard that never reported all look exactly like that. Worse, mutmut's own status map records pytest's INTERNAL ERROR as a kill (`3: "killed"  # internal error in pytest means a kill`), and contention produces that exit on a tree whose every test passes — so a loaded run could report entries refuted with no timeouts to show for it, while a quiet run on the same tree reported the same mutants surviving. Three things change. Absence can no longer reach `refuted` by any path: membership in the survivors and in the kills are both positive observations and are tested as such, and a mutant the run never settled is reported as unmeasured with the run reading UNKNOWN rather than FAIL. A kill is read from the raw pytest exit code rather than mutmut's status word, so only "tests ran and failed" counts as a test having observed the mutant, and anything else — including an exit code nobody has met yet — is not a detection. And a refutation must be corroborated by re-running that one mutant in isolation, with the re-run judged for load on the same terms, because it meets the same contention and "not a survivor on the second try" is not agreement. A real distinguishing input still reaches `refuted`, which is what keeps the gate able to report a stale claim at all.

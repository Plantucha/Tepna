`tools/sync-main.sh` advances a checkout's local `main` to `origin/main`, but only when that is
provably safe — so it can run unattended on a timer.

WHY. Nothing in this repo fetched on its own: no cron, no timer, no git hook, no tool. The discipline
was purely manual and it had drifted — local `main` in the shared root was measured **47 commits
behind with a clean tree** on 2026-08-16. The vigil box drifts the same way and is worse, because
nothing there fetches at all: its `HEAD..origin/main` count reads **0** while it sits commits behind,
since a ref comparison cannot see staleness it never downloaded.

WHAT MAKES IT SAFE, and why it is not the obvious one-liner. The plumbing ref-movers move the REF and
touch neither tree nor index — and one of them skips git's checked-out-branch check entirely. If the
branch is checked out, the tree then freezes while HEAD advances, so every file a later merge ADDS
reads as `deleted` (CLAUDE.md §👥.2b; 47 live files, growing with each merge). `merge --ff-only`, run
in the checkout that HOLDS the branch, moves tree + index + ref together and refuses outright on
divergence. That is the only form this script uses.

It refuses rather than guesses, on every axis:

| condition | action |
|---|---|
| an operation in progress (rebase/merge/cherry-pick/bisect) | SKIP — its "clean tree" would be a lie |
| the checkout is not on `main` | SKIP — never advance a ref another worktree holds |
| **any** uncommitted or untracked path | SKIP — that is someone's in-flight work |
| local has commits origin lacks | **REFUSE** (exit 3) — unpushed work, not staleness |
| clean, behind, fast-forwardable | fast-forward, and say by how much |

It never resets, checks out, stashes, cleans, or force-moves a ref; every failure path leaves the
checkout exactly as found. It measures the TREE (`status --porcelain`), not the ref count — the
comparison that returned 0 while a tree was 214 files stale.

Bash rather than Node deliberately: the vigil box has no node and needs this most.

Verified by exercising each guard until it was SEEN to fire — dirty tree (work survived), diverged
(local commit intact), clean-and-behind (fast-forwarded, content correct), and idempotent re-run. An
earlier pass of that test was **vacuous** — the clone was made after origin advanced, so it was already
current and the fast-forward path never ran; it is recorded here because the silent-pass shape is this
repo's recurring defect. Clean under `shellcheck --severity=style`, which caught two real SC2140
quoting bugs before CI would have.

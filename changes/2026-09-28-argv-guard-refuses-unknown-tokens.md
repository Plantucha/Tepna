A token `tools/trio-batch.mjs` cannot interpret now refuses with exit 2, naming the token and the nearest documented flag, before anything is planned or written. The idiom across `tools/` is `flag = (n) => argv.includes(n)` and `opt(n, d)`, each looking up only the names it knows, so a token nobody looks up was indistinguishable from an absent one — and the default it fell back to was not neutral but whatever the tool does when the flag is off, which for a dry-run flag is the WRITING branch. Measured: `--dry` for the documented `--dry-run` printed a per-night plan, computed, and wrote two exports of an unstamped night, while the tool's own help promised "compute nothing, write nothing". The refusal lives in a new shared `tools/argv-guard.mjs` rather than as a bespoke block, so the next adopter costs two lines; trio-batch is the only adopter here. Arity is part of the spec, because a guard that walked tokens without knowing which flags consume a value would refuse `--night 2026-06-20` and turn a correctness fix into a tool nobody can run — so a valued flag with no value after it, and a valued flag that would swallow the next flag, are refusals of their own, and `--flag=value` is refused because `opt` reads the next token and would otherwise ignore a form it accepted. The declared set is what the code READS, not what the header documents: trio-batch reads four flags its help never mentions (`--cpap`, `--only-node`, `--allow-partial`, `--child`), one of them passed by its own child dispatcher, so a spec built from the help would have refused its own children — and a test asserts that every flag reachable from a `flag(`/`opt(`/`optAll(` call site is declared. A suggestion prefers a flag the token is a PREFIX of over the closest by edit distance, because `--dry` is distance 2 from `--src` and 4 from `--dry-run`, so a pure-distance answer names the wrong flag for the one slip this exists to catch.

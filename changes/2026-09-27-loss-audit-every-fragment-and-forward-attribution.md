The loss audit now examines every fragment of a device's primary stream and finds a gap's cause on the side of the gap the daemon actually logs it. Two instrument defects, one PR. `audit_night` audited ONE file per device — `max(files, key=getsize)` — so on a fragmented night the ledger read as the whole night while most of the recorded span went unexamined (measured on vigil 2026-09-24: 2026-09-10 H10 4 files, 53.7 % of span unaudited; 2026-09-19 Verity 5 files, 55.2 %; 2026-09-05 ring 32 files, 18.7 %), while the `wear` block beside it already walked every file. It now scans all of them, chronologically by each file's own first row, and counts the gaps BETWEEN fragments — a boundary is a delivery event, so "sum the files' gaps" would miss exactly the loss that made the night fragment. Each boundary is judged like an in-file gap, by the device counter (#3157): advancing across it by much less than the host gap is late delivery, advancing by the whole gap is loss, and three cases where the counter cannot answer — no counter at either endpoint, no period learnt, or a counter that went BACKWARDS because a reconnect reset it — fall to loss, the direction that cannot silently forgive a hole. `attribute_gaps` searched only backward from a gap's start, but the start is the stream's last delivered row and the daemon logs the causing action after it: measured over the H10 2026-09-17→23, all 39 real-loss gaps had their `pull paused live` line 1–3 s after the start and none before it, so every one read `unattributed` and inflated SOLID-NIGHT's unattributed leg with the daemon's own designed behaviour. Attribution now reaches `ATTRIB_FORWARD_S` past the start as well, nearest event wins, with the backward candidate kept as `backward_cause` and any event deeper in the outage published as `in_gap_cause` but never used as the attribution — a wider window taking the first event anywhere in the gap was tried and refuted by an existing assertion, where it handed a 121 s gap to a `dbus busy` 101 s deep over a `not-worn drop` 1 s before the start. `stream_scan` replaces `stream_gaps_split` as the scan entry point because a boundary needs each file's endpoints on both clocks; the verdict object's shape and population are unchanged, single-file nights are audited exactly as before, and a gap entry gains provenance fields additively.

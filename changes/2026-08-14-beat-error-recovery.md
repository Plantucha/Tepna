`tools/beat-error-recovery.mjs` — target 6 of the known-clock experiment: inject beat-detection errors of known type and rate into a real RR train, run the shipped HRV path, measure the damage. Self-tested, seeded, deterministic. Run over 101 real H10 nights (median 1440 beats, median true rMSSD 44.6 ms). **The headline: one missed beat in a thousand inflates rMSSD by 20.8 %**, while mean RR moves 0.06 % — so a summary HR looks perfect while the HRV metric is a fifth wrong. For scale, a 30 ppm clock error over a 7 h night moves rMSSD by ~0.003 %, because rMSSD is a first difference and a smooth rate error cancels; a missed beat fuses two intervals and rMSSD is quadratic in that. Detector accuracy and clock accuracy are not comparable quantities and the suite had been measuring the smaller one. At heavier corruption the raw inflation reaches +387 % (2 % miss) and +614 % (5 % miss). Malik correction removes the injected damage but lands on the SAME value regardless of what was injected (−22 % at both 0.1 % and 5 % miss), i.e. it converges on its own flattened estimate rather than on truth. **What the experiment cannot decide, and the brief says so:** the NULL row's −21.95 % is either a corrector bias or the correct removal of ~22 % of genuine artefact inflation in the as-recorded train — separating them needs independently adjudicated R-peaks, which this corpus lacks. Do not cite it as "Malik is biased". What it does establish is magnitude: correcting a median of 3 beats in 1440 moves rMSSD 22 %, because rMSSD's extremes dominate it. Also measures the cost of using the WRONG corrector — the suite intentionally applies 0.20 to ECG/Pulse and 0.30 to optical PPG — and reports both legs side by side. Records a third instance of this session's recurring tool bug: the tool read `correctRR`'s return as `rr|corrected|out` when the shipped shape is `{nn,tt,nCorr,flags}`, so the first corpus run printed "after Malik: n/a" across all 101 streams while the corrector ran fine. Regression assertions now require both corrector legs to be populated.

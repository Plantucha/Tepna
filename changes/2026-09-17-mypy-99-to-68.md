capture-host's mypy count drops **100 → 68** and the ratchet is banked (`MYPY_BASELINE` 99 → 68). The
gate flips BLOCKING at zero, so every error closed is permanent.

⚠️ **The starting number was neither of the two on record.** The brief header says 102 (2026-09-03),
`check.sh` said 99 (2026-09-13); measured on `origin/main` at `59aa0f3c` with check.sh's own invocation
it was **100 in 32 files**. A bare `mypy .` reports 1 and stops — it dies on a package-bases error before
finishing — so the invocation matters more than the number does.

Five root causes, not 32 fixes. Each was one wrong declaration producing a cluster:

* **`callable` used as a type** (4 files) — it is the builtin predicate, not `Callable`, so it meant
  nothing to the checker and every call through it errored too. **11 closed.** Replaced with the precise
  signature each site holds (`Callable[[], float]` for `monotonic`, `Callable[[], str]` for the wall
  clock), not a blanket `Callable[..., Any]`.
* **`nightqc`'s arrival map annotated `list[float]` while every append is a 3-tuple** —
  `(host_ms, host_ms − device_ms, device_ns)`. The append errored and so did everything downstream that
  unpacks it ("float is not iterable", "not indexable"). **10 closed by one declaration**, none of them a
  real defect.
* **`_NOMINAL_HZ` mixes int and float literals**, which mypy joins to `object`, so `.get` read as a call
  on `object`. Annotated `dict[str, dict[str, float]]`.
* **`_anchor_wall` is a `datetime | None` global that mypy cannot narrow across the `_reanchor()` call
  that sets it** — so `anchor + timedelta` read as `None + timedelta` and three `return predicted` as
  `datetime | timedelta`. **5 closed** by having `_reanchor` return the anchor it just set and binding a
  local. Costs the 130 Hz path nothing: one local read where it was a global read plus a None test.
* **`_CPAP_AUTOSTART` literal initialises both slots to `None`**, fixing the value type. Annotated.

⚠️ **One real latent crash was found and fixed, and one `object` annotation was tried and reverted.**
`best_s` in the lattice scan started as `None`; every `r` is an `abs()` so it never exceeds the initial
`0.0` when the vector sum cancels exactly, and the refine loop would then multiply `None`. Seeded with a
real candidate rather than guarded with a branch nobody can reach to test — a scan that finds nothing
returns `R: 0.0`, which is already this function's signal for "no periodicity". And `_CPAP_AUTOSTART:
dict[str, object]` merely moved the error to the read (`observe_start` got `object` instead of `None`);
`Any` is the honest description of heterogeneous cross-restart state.

No behaviour was changed except that latent crash. 7282 tests pass, coverage 100.00 %.

**68 remain**, the largest clusters being `arg-type` (~24) and `Any | None` values flowing into
non-optional parameters. Incremental by design: the count may only go down.

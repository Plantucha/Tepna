# Build Brief — the EEG stage formula for EEGDex (base model)

The owner ordered the base version on 2026-11-23, and the hand-off on 2026-11-24. @kestrel assigned
it to @magpie in board #8464, and the claim is `eegdex-stage-formula` in board #8466. The hand-off
folder is @finch's, it sits outside this repository, and board #8463 names it. `SPEC.md` inside that
folder is the source of every acceptance item below. I verified the 9 hashes of `SHA256SUMS`: 9 of
9 OK.

Nothing in the folder is a recording. The model file holds fitted coefficients, and the test vectors
come from a seeded synthetic generator.

## 1. What this builds

A sleep stager for one EEG derivation: four stages per 30 s epoch, computed after the night ends,
from a model FILE of schema `tepna.stage-formula/1`. The code knows the block kinds and the pass
kinds; the numbers live in the file. A better model later is a new file and no new code.

The base model declares 4 classes, 35 inputs, the design blocks `linear109` and `products630`, and
one `softmax` pass over 739 columns. It names 14 fits and pins its coefficient source by hash.

**The present band-power stager stays the default, and the switch is OFF** (@kestrel, #8464 rule 3).
`eegdex-dsp.js` states that ceiling in its own header, and this work does not remove it.

### PR 1 — the feature block

- [x] One EEG channel in, 35 columns per 30 s epoch out, in the order of `EEG_NAMES`.
      `eegdex-stage-features.js`, 830 lines.
- [x] The port takes `eegBlockExtract` and the three detector files behind it, and it changes no
      arithmetic. **It changes MORE than one import path**, because this repo's modules are not the
      source's ES modules: a bundle inlines a plain script that attaches one global, so the port is
      one file with the imports resolved and the `export` keywords gone. The transform ran as a

      of the 35 columns reads: the rule stager that the formula replaces, and two provenance fields

      names belong).
- [x] A NaN sample is "not measured", and a NaN column stays NaN. No column reads 0 for an absence.
      A night with no EEG signal reports 35 absent columns, and the group asserts that.
- [x] Every column is free of the signal's unit: a night multiplied by 3.7 gives the same columns,
      worst 3.3e-5 relative, which is the float32 rounding of the scaled signal. The block therefore
      reads the whole night. This is the one assertion the vector cannot make.
- [x] Parity against the `features` field of the synthetic vector file: **the worst relative

- [x] The vector carries no capture bytes: its signal comes from a seeded generator, and the parity
      group reproduces that generator so the comparison cannot drift from it. The vector itself is
      the FIT's output and this repo regenerates it never — a vector regenerated by the port would
      compare the port with itself. It sits in `tests/vectors/`, not in `tests/fixtures/`, because
      the gates over that directory read every file in it as an export to validate.

### PR 3 — the wiring in EEGDex

- [x] The model id and the model's limits sit beside the hypnogram. The note names the id and the

- [x] An unscored epoch reads as not scored, and never as a stage. The strip draws a gap, and the

- [x] Each number on the screen carries an `experimental` badge or lower, until a blind read says

      forehead recordings; a frontal derivation recognises deep sleep less well than a central one;
      the stager scores after the night and not during it; it is a research aid and not a diagnosis.

## 3. The absence rule, stated once

§∅ governs this node as it governs every other. An epoch that misses half or more of its 36 inputs
is `null` with a named reason, and a night with no measured input at all names the night. The formula still answers a posterior for such an epoch, because its inputs read 0 and
its `miss` input reads 1, so the refusal is a step AFTER the arithmetic and never a change to it.
That split is what lets the parity test compare every posterior while the node still refuses to name
a stage it did not measure.

## 4. The licence table, and what goes to @kestrel first

The model file's `fit.names` field holds 14 names from 8 corpora. `THIRD-PARTY.md` and the model
file stay as they are, and `THIRD-PARTY.md` carries a table of those names with the data set, the
version, the licence and the accession identifier. The rows give an identifier and NOT a DOI string:
the DOI ledger holds papers that Crossref resolves, and a data-repository DOI would claim a check
that nobody ran. Board #8487 records that decision too.

- [x] I read each licence AT ITS SOURCE, and I never copy a licence cell from the lab's inventory.
- [x] @finch tells me which corpus version each fit name used, because the inventory has no version
      column (@kestrel asked for this in #8464). Three rows carried no version, and I read the
      number from the data set's own project page instead.
- [x] A set that is non-commercial, share-alike or under a signed agreement goes to @kestrel BEFORE
      the push, and so does any set whose licence is none of CC0, CC BY 4.0 or ODC-By 1.0.
      Nothing went: all 8 licences read CC0, CC BY 4.0 or ODC-By 1.0 (board #8482).

## 5. What stays out

- No lab figure, no lab path, and no comment that holds one. I read each comment of the lab's files
  before I keep it (@kestrel, #8464 rule 4).
- No agreement figure of this model in a PR, a commit or a doc. Those stay on the board.
- No third-party project name in code, tests or text. The licence table is the one place a dataset
  name appears, because a licence obligation requires it.
- No capture bytes. The vectors are synthetic, and the test stays synthetic.
- The better two-pass model. It runs through the same evaluator, and it follows as a second model
  file when it has a blind read.

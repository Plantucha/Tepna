# Residue ledger — defects a brief left behind, one row each, promoted on pickup

**What this is.** When a brief is executed or triaged and something verified is still wrong, it goes
here as **one row**, not as a new `-FOLLOWUPS-` brief. A follow-up brief is written **only by the
session that picks the row up to execute it** — so every follow-up brief has an owner the moment it
exists. Measured 2026-09-02 (the drain): 27 of 77 open briefs were `-FOLLOWUPS-` files created at
execution time, and none of them had an owner, because "spawn a follow-up" creates the file before
anyone has decided to do the work.

**Row contract** (gate-backed — `docs-ledger` check 8 in `tests/dex-tests.js`):

| column | rule |
|---|---|
| key | **`YYYY-MM-DD-short-slug`** — the date the row was written plus a few words naming the defect (`2026-09-02-oxyii-acks-unparsed`). Lowercase, digits and hyphens. Unique **by construction**, not by allocation: it needs no lookup, no counter and no coordination, and it reads in a back-reference |
| logged | `YYYY-MM-DD` the row was written |
| source | where the residue came from, backticked. Usually a `*-BRIEF.md` that left it — must exist, and its **Status:** line must carry `**Residue:** <key>` (bidirectional, like `Superseded-by`). **A residue with no parent brief names its real origin instead**: a repo path (`capture-host/tools/find_unwired.py`), which must exist in the tree, or a `#NNNN` PR. Non-brief sources neither need nor can carry a back-reference |
| defect | what is wrong — a verified defect, not a wish; **no `\|` in the cell** (a pipe splits the row and blinds the gate — measured on DOCS-INDEX 2026-09-02) |
| evidence | the line / hash / count / command that shows it — prose is not evidence |
| state | `OPEN` · `→ \`<NAME>-BRIEF.md\`` (promoted to a brief at pickup — that brief must exist) · `fixed #NNNN` (closed by one PR, no brief needed) |

A row is closed by changing **only** its state cell. Nothing else on a row is ever edited; a wrong
row gets a new row that says so.
⚠️ **One exemption, and it is self-limiting: repairing a POINTER.** A reference to another row's
identity is not a claim about the world — it is a pointer, and the 2026-09-02 rename broke every one of
them. Replacing a retired `R<n>` with a backticked key that names a real row PRESERVES the claim;
leaving it dangling alters it, because the row then points nowhere. `residue-ids` permits exactly that
substitution and nothing else, checkable from the two versions of the file alone with no rename map and
no author's assurance — and once no `R<n>` survives anywhere it can never fire again.
Open count: `grep -cE '^\| [0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9-]+ \|.*\| OPEN \|' briefs/RESIDUE.md`
(verified 2026-09-02: 20 matches against 20 open rows, and 0 non-row lines match).
⚠️ The obvious form — `grep -c '| OPEN |'` — **counts this instruction line too**, because the line
quoting the pattern contains the pattern. It read 17 against 16 open rows on 2026-09-02. Anchor on a
row, not on a substring that your own documentation matches.

🔴 **Why the key is a date-slug and not `R<n>` (changed 2026-09-02, after FIVE collisions in one day).**
The ledger opened with a sequential counter. Two branches then minted the same number five times —
`R11` twice, `R12`, `R13`, `R15` — and the last one happened **within the hour of the rule being
argued out, between the two sessions arguing it, each having run the prescribed pre-push check and each
having received a correct answer from it.** The diagnosis is not carelessness and not staleness:
`origin/main` **cannot contain an id claimed in an open branch**, so the check the scheme demanded could
not return the right answer. Closing that properly meant enumerating every open PR's diff over the
network, racing anyone who pushed meanwhile, enforced by nothing.

> **A globally-unique identifier allocated from local information has no correct procedure.** Not a slow
> one, not an expensive one — none. The fix is not a better check; it is an id that needs no allocation.

Briefs and changesets in this repo have always been dated-slug and **neither has ever collided**; the
ledger was the only artifact inventing an allocation problem. The old `R<n>` keys were renamed in place
by one migration — the single exception to "a row is never edited", and it is recorded here rather than
performed quietly. `R7` never existed: it was announced in a message, minted around, and never written.

⚠️ **Never name the nearest brief to fill the source cell.** A residue surfaced by *repairing an
instrument* has no parent brief — the two orphans `find_unwired.py` found on 2026-09-02, once it
stopped counting a comment as a consumer, descend from the tool fix and from nothing else. A false
source **passes** check 8 (which verifies existence and the back-reference, not responsibility) while
sending whoever picks the row up to a brief that never left the defect. That is the fabricated
authority this ledger exists to prevent, committed inside the ledger. Name the origin that is true.

**Not retro-applied.** The `-FOLLOWUPS-` briefs that already exist keep their files and headers; this
ledger starts empty except for the residue named in the 2026-09-02 drain headers.
